這張證照在證明什麼

PCA 不考你會不會點主控台，而是考你拿到一份商業需求時，能不能選出最合適的 Google Cloud 架構，並說得出取捨。幾乎每題都是情境題：一家公司、一串限制、四個「技術上都能動」的選項，你要挑出最符合條件的那一個。

官方建議有 3 年以上業界經驗、其中 1 年在 Google Cloud 上設計與管理方案，但沒有報考門檻。如果你來自 AWS 或 Azure，大部分架構觀念可以直接帶過來，主要差在服務名稱與 Google 特有的設計（例如 VPC 是全球資源）。這些在「基礎觀念」一章有對照表。

答題策略

Google 偏好的答案長什麼樣子

先看最後一句

先找出題目要你最佳化什麼（最便宜、最少維運、最快、最安全），再回頭從情境找限制條件。

代管優先

能力相同時，選全代管、可自動擴展、Google 官方推薦的服務。自建、手動、寫 script 輪詢通常是干擾選項。

最小權限

Predefined role 優於 basic role；授權給群組優於個人；Workload Identity Federation 優於下載金鑰。

剛好滿足需求

題目只要 99.9%，就不必多區域 active-active。過度設計在成本題一定錯。

預防勝於偵測

Org Policy、VPC Service Controls 這類事前阻擋的控制，優於事後寫程式偵測再刪除。

案例條件至上

案例寫「暫不搬遷」「經銷商沒預算」「可靠度與成本最優先」，違反這些條件的選項直接刪掉。

第 2 站 · 基礎觀念

讀考綱之前要先有的七個觀念

考綱裡的每一條，幾乎都建立在這幾個觀念上：資源放在哪裡、誰能動它、流量怎麼走、錢怎麼算、壞掉時怎麼辦、怎麼搬上來、用什麼標準評價設計。這一章把它們講清楚，後面讀到不懂的名詞，也可以按右下角的「查名詞」。

觀念 1

資源放在哪裡：全球、區域、zone

Google Cloud 的機房分成區域（region），例如台灣彰化的 asia-east1、東京的 asia-northeast1。每個區域裡有 3 個以上互相獨立的可用區（zone），各自有獨立的電力與網路，例如 asia-east1-a、-b、-c。

每一種資源都有自己的「範圍」，而範圍決定了它會被哪一種故障影響。這是可用性題目的底層邏輯：要撐過 zone 故障，就把服務放成 regional；要撐過整個區域故障，就要多區域。

範圍例子能撐過
Zonal單一 VM、zonal Persistent Disk、zonal GKE 叢集無法撐過該 zone 故障
Regional子網路、區域 MIG、regional GKE、Cloud SQL HA、Cloud Run 服務、regional bucket、Spanner regional單一 zone 故障
Multi-regional / GlobalVPC 網路、全球負載平衡器、multi-region / dual-region bucket、Spanner multi-region、BigQuery multi-region dataset、IAM單一區域故障
觀念 2

誰能對什麼做什麼：資源階層與 IAM

所有資源都掛在一棵樹上：Organization → Folder → Project → 資源。Project 是計費與隔離的基本單位，類似 AWS 的帳號或 Azure 的訂閱。Folder 用來依部門或環境分組，方便一次套用政策。

權限由 IAM 政策決定。一條授權（binding）由三個部分組成：

誰 · group:ops@example.com＋角色 · roles/compute.instanceAdmin.v1＋範圍 · Folder「Production」

三種角色

  • Basic：Owner、Editor、Viewer。權限範圍太大，考試中幾乎不會是正解。
  • Predefined：Google 依服務設計好的角色，例如 roles/bigquery.dataViewer。預設首選。
  • Custom：自己挑權限組合。Predefined 給太多時才用，但要自己維護。

四個關鍵規則

  • 繼承：在上層授權，下層全部自動拿到，而且下層拿不掉（除非用 deny policy）。
  • 授權給群組：人員異動時改群組成員即可，不必改政策。
  • 服務帳戶是給程式用的身分。掛在 VM、Cloud Run 上使用，避免下載金鑰。
  • Org Policy 限制「資源可以怎麼設定」（例如只能建在 EU、禁止外部 IP），和 IAM 管「誰能做」是兩回事。

觀念 3

流量怎麼走：VPC 網路

Google Cloud 的 VPC 是全球資源，子網路才屬於區域。所以同一個 VPC 裡，台灣和東京的 VM 可以直接用內部 IP 互通，不需要另外接 VPN。這是和 AWS、Azure 最大的差異之一。

VPC 防火牆規則是有狀態的：回應流量自動放行。預設的隱含規則是「拒絕所有進入、允許所有外出」。規則可以用網路標籤或服務帳戶指定套用對象；整個組織共用的規則用階層式防火牆政策統一管理。

網路題最常見的困擾是「要連到某個地方該用什麼」。先分清楚目的地，再看頻寬與 SLA：

我要連到…用什麼
網際網路（VM 沒有外部 IP）Cloud NAT：只能往外連，外面連不進來
Google API（Cloud Storage、BigQuery），VM 沒有外部 IPPrivate Google Access；想要內部 IP 端點則用 PSC for Google APIs
同一個 VPC、不同區域直接互通，不需任何設定（VPC 是全球的）

觀念 4

錢怎麼算：計價模式與成本控管

成本題的答案是「剛好滿足需求的最便宜方案」。要選得出來，得先知道錢花在哪裡。

運算

  • 隨需：按秒計費，沒有承諾。
  • 持續使用折扣（SUD）：部分機型在一個月內跑越久，自動越便宜，不用申請。
  • 承諾使用折扣（CUD）：承諾用 1 年或 3 年換取折扣。適合 24 小時穩定的基礎負載。
  • Spot VM：比隨需便宜 60–91%，但隨時可能被回收。適合可重跑的批次工作。
  • 縮到 0：Cloud Run 等無伺服器服務閒置時不收運算費。

儲存與網路

  • Cloud Storage 費用 = 容量 + 操作次數 + 取回費。越冷的類別容量越便宜，但取回越貴，而且有最短儲存天數（提早刪除仍收足天數）。
  • 網路：流入免費；同 zone 內部 IP 傳輸免費；跨 zone、跨區域、流出到網際網路要收費。所以「把資料和運算放在同一區域」本身就是一種省錢設計。

控管工具

  • 預算與告警：只會通知，不會自動停止花費。
  • 帳單匯出到 BigQuery ＋ 標籤：分析每個團隊、環境花了多少。
  • Recommender：建議縮小規格、刪除閒置資源、購買 CUD。
觀念 5

可靠性的語言：SLA、SLO 與可用性計算

四個詞

  • SLI：實際量到的指標，例如「成功請求的比例」。
  • SLO：團隊內部訂的目標，例如「30 天內 99.9% 成功」。
  • SLA：對客戶的合約承諾，沒達到要賠償。通常比 SLO 寬鬆。
  • 錯誤預算：1 − SLO。99.9% 的 SLO 代表每月可以「花掉」約 43 分鐘的失敗；預算用完就該暫停發布、先修穩定性。

可用性計算器

一個請求要依序經過好幾個元件時（串聯），整體可用性是各元件相乘，一定比最弱的那個還低；同樣的系統在兩個區域各放一套並能自動切換時（並聯），整體可用性會大幅提高。預設數字是各服務常見的 SLA，可以自己改。

怎麼搬上來：遷移的 6R

遷移題會描述一個系統的狀況，要你判斷用哪種策略。Google 的遷移流程是評估 → 規劃 → 部署 → 最佳化，所以「第一步」通常是用 Migration Center 盤點。

策略做法題目訊號Google 工具
Rehost原樣搬 VM（lift & shift）時程緊、不能改程式、機房租約到期Migrate to Virtual Machines、VMware Engine
Replatform小幅調整，換成代管服務想減少維運但不想大改，例如 MySQL 換成 Cloud SQLDatabase Migration Service、Migrate to Containers
Refactor改寫成雲原生架構要擴展性、敏捷度，有時間和人力GKE、Cloud Run、Pub/Sub

第 6 站 · 案例研究

四個官方案例，考試抽兩個

案例題佔 20–30%，而且題目只會給一兩句話，背景全在案例裡。考試時可以分割畫面看原文，但每題重讀會來不及。目標是考前把每個案例讀到「看到公司名就想得起架構」。

步驟 1

找出最在乎什麼

先讀高層聲明與商業需求，抓出優先順序。這是兩個選項都可行時的裁判。

步驟 2

圈出不能做的事

暫不搬遷的系統、沒預算的對象、法規區域。這些條件會直接刪掉選項。

步驟 3

每條需求配一個服務

用下方的「需求 → 解法」卡片自我測驗，先想答案再點開。

步驟 4

畫出目標架構

把服務連成一張圖。考試時腦中有圖，就不必回頭翻原文。

第 7 站 · 練習與模擬考

56 題原創情境題

依考綱與官方案例撰寫，風格貼近正式考試：長情境、找限制條件、選「最佳」而非「可行」。作答後每個選項都會顯示對或錯的理由，請確定自己說得出「為什麼其他三個不對」再往下。熟悉之後切到模擬考：隨機 20 題、48 分鐘（與正式考試每題約 2.4 分鐘的節奏相同），交卷後才看答案。

第 8 站 · 速記卡

考前一天的數字與定義

SLA、最短儲存天數、頻寬、日誌保留期這類細節，在選項裡常是決勝點。點卡片翻面，按「記得」或「還不熟」標記，之後可以只複習還不熟的卡片。
